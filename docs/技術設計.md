# 技術設計

## 1. 方針

- **ビルド不要の素のJavaScript＋Canvas**。ライブラリなし、npm なし。`index.html` を開く（ローカルサーバー経由）だけで動く
- 有料のサービス・素材は使わない。ドット絵はコード内に文字で描き、音はブラウザ内で合成する
- 数値（バランス）とターゲット定義はデータファイルに分け、ロジックを触らずに調整できるようにする
- PC・スマホの両方で 60fps を目指す（描画は低解像度なので軽い）

## 2. 画面サイズと描画

- 内部解像度：**320×180**（16:9）のキャンバスに描く
- 画面に合わせて **整数倍** に拡大（余りは黒帯）。`image-rendering: pixelated` でドットをくっきり
- スマホの切り欠き対応：`viewport-fit=cover` と `env(safe-area-inset-*)` の分だけ、キャンバス内のボタン位置を内側へずらす
- **ボタン・HUD・メニューもすべてキャンバスに描く**（HTMLの文字はドットにならないため）。タップ判定は `input.js` で画面座標 → 内部座標に直して行う
- 描画順：地面タイル → 影 → 物（y座標順に並べて奥行きを出す） → エフェクト（ハート等） → おねだり照準（矢印・確率） → HUD・ボタン
- Babylon.js などの3Dエンジンは使わない（2Dドット絵には重く、ドットがにじみやすいため）

### ドット文字

- フォント：美咲フォント（8×8）と k8x12（8×12）。どちらも無料で配布・同梱できるライセンス。`fonts/` に置き、ライセンス文も同梱する
- 描き方：起動時に `FontFace` で読み込み → 文字列ごとに小さな裏キャンバスへ **フォントの設計サイズちょうど**（8px／12px）で描く → 半透明のピクセルを「塗る／塗らない」に二値化して、にじみをなくす → 結果をキャッシュして使い回す
- 拡大はキャンバス全体の整数倍拡大だけに任せる（文字だけ別の倍率にしない）
- 数字と英字は太めの自作 5×7 ドットも用意して、スコアなどの大きい表示に使う

## 4. ゲームループ

- `requestAnimationFrame` で回し、更新は **固定 1/60 秒刻み**（端末の速さに左右されない）
- 1フレームで追いつく更新は最大5回（重い端末で固まらないように）
- タイマー類（残り時間・お水・爪とぎ・トイレ）は更新の中で `dt` を引いていく。ポーズ中は更新しない

## 5. シーン管理

スタック式。上に積んだシーンだけ更新し、描画は下のシーンも描く（ポーズで後ろの街を薄く見せるため）。

```
[play] → push(ringing) → pop → [play]
[play] → push(pause)   → pop → [play]
[play] → push(kamaware)→ pop → [play]
[play] → replace(result)
```

`play` が持つ「プレイ状態」（下記）は、`ringing` などに参照で渡す。

## 6. 主なデータの形

```js
// プレイ中の状態（1プレイ分）
playState = {
  stageId, timeLeft,           // 残り秒
  paused,
  tp, tpEarnedTotal,           // 今のTP、獲得合計（スコア用）
  fp, fpEarnedTotal,           // トイレ用の端数、獲得合計
  kamawareScore,
  faintCount,
  cat: {
    x, y, dir, speedBase,
    weight,                    // 0〜100
    thirst,                    // お水：最後に水を飲んでからの秒数
    buffs: { scratch: 0, toilet: 0 },  // 残り秒
    state: 'walk' | 'scratch' | 'drink' | 'toilet' | 'faint' | ...
  },
  targets: [ { defId, x, y, cooldown, state } ],
  items:   [ { kind, x, y, life } ],
  aim: null | { pointerId, dirX, dirY, candidates:[{target, chance}], selected },
}

// ターゲット定義（data/targets.js）
{
  id: 'salaryman',
  name: '棒立ちの会社員',
  kind: 'human',               // human | animal | robot | landmark
  legs: [ {x:-6,y:0,r:3}, {x:6,y:0,r:3} ],  // 足の位置（ズーム画面座標）と太さ
  motion: 'still',             // still | stomp | wander | patrol | frantic
  durability: 2,
  tp: 2,
  drops: null,                 // { item:'bread', count:4 }  成功時に散らばってハートと一緒に吸い込まれる
  stages: [1,2,3,4],
  onedari: { base: 0.40, perTp: 0.010 },  // おねだり成功確率。null なら対象外（ロボ・ランドマーク）
}

// 保存データ（localStorage 'teramaru.save.v1'）
{ version:1, coins, bestScore:{1:0,2:0,...}, unlockedStages:[1], archive:{}, settings:{mute:false} }
```

**保存の差し替え（将来のログイン用）**：`save.js` は `load()`／`save(data)` だけを外に見せ、中身（いまは localStorage）を差し替えられるようにする。ログインを付けるときは、サーバー保存版を同じ形で作り、初回ログイン時に端末のデータを引き継ぐ。コインは将来お金に近い扱いになりうるので、そのときは加算をサーバー側で検証する（端末保存のうちは改ざんできる前提）。

## 7. 入力

`input.js` が3種類の入力をまとめて、毎フレーム次の形で返す。ゲーム側はどの機器かを気にしない。

```js
{ move: {x, y},        // 長さ0〜1のベクトル
  confirmPressed,      // このフレームで押された
  pausePressed,
  aim: null | { phase: 'start'|'hold'|'release', dirX, dirY, key: true|false } }
```

マウスとタッチは Pointer Events でまとめて扱う。指が押されたとき、**どこを押したか** で役割を決め、その指が離れるまで変えない。

| 押した場所 | 役割 |
|---|---|
| ボタン（決定・ポーズ・メニュー） | そのボタン |
| てらまるの上（見た目の16ドットより広く、半径14ドット） | おねだり照準。てらまる → 指 の向きを `aim` に入れる。離したら `release` |
| それ以外 | 移動。マウスはてらまる → カーソル の方向（近いほど弱く）、タッチは押した場所を中心にスティックを出す |

- キーボード：WASD・矢印で `move`（斜めは長さ1に正規化）。決定キーを0.2秒以上押すと照準開始、方向キーは `move` ではなく狙いの切り替えに使い、離したら `release`。短く押したときは爪とぎなどの決定
- スマホは2本指まで扱う（移動しながら別の指で決定ボタンなど）
- 複数の機器が同時に来たら、最後に触った機器を優先
- ボタンは `pointerdown` で反応（遅れないように）。ダブルタップ拡大・スクロール・長押しメニューはCSSと `preventDefault` で止める

### おねだり照準（onedari.js）

- 照準開始：TPが10以上なら `playState.aim` を作る。照準中は `play` シーンのゲーム更新（移動・タイマー・お水等）を止め、見た目用のアニメ時計だけ進めて、キャラにその場の小さな揺れ（ぴこぴこ）をさせる
- 毎フレーム：てらまるから一定距離内の「おねだりできるターゲット」を集め、`min(1, base + tp × perTp)` で確率を計算 → 頭上に表示
- 狙い：指の向きとターゲット方向の角度差が45°以内で、いちばん角度差が小さい（同じなら近い）ものを選ぶ
- 離したとき：狙いがあればTPを全部消費して飛びつき → 抽選 → 成功なら `kamaware` シーンへ。狙いがなければ何もしない

## 8. てらまりんぐの判定

- てらまりんぐ画面ではターゲットの足元を真上から見た座標系に切り替える
- 足ごとに、前フレームと今フレームの「足から見たてらまるの角度」の差を足していく（`atan2` の差を −π〜π に直してから加算）
- 足からの距離が `r + 4` 〜 `r + 28` ドットの輪の中にいるときだけ加算。外に出たら加算を止めるが値は保持
- 合計の絶対値が 2π を超えるごとに1周 → その足を「回った」印、メロメロゲージ +1
- 成功条件：全部の足に印 かつ ゲージ ≥ 耐久度
- 1回ごとの制限時間はなし。プレイの残り時間はこの間も減る。画面の端から出たら中断
- 足の動きは `legs.js` のパターン関数 `position(t)` で計算し、てらまると円同士の当たり判定
- 体重による曲がりにくさは、入力方向への向き変更の速さ（旋回速度）を下げて表現する

## 9. 乱数とテスト

- 乱数はシード指定できる `rng.js` を通す（おねだりの確率などを再現できるように）
- URLに `?debug=1` を付けると：当たり判定の表示、時間停止キー、TP+50キー、ステージ全解放
- 判定まわり（周回カウント、成功確率、スコア計算、コイン換算）は副作用のない関数にして、ブラウザで開く簡単なテストページ `tests.html` で確認する

## 11. 公開

- 当面は自分たちだけで遊ぶ。ローカル（`python3 -m http.server`）か、同じWi-Fiのスマホで確認
- いずれ公開する。静的ファイルだけなので GitHub Pages などに無料で置ける
- 公開に備えて：フォントは再配布できるもの（美咲フォント・k8x12）だけを使いライセンス文を同梱する。外部の画像・音素材は使わない。家の写真はゲームのフォルダに入れない（模様は仕様書の文章とドット絵だけで持つ）
- ES Modules を使うため、`index.html` をダブルクリック（file://）では動かない点に注意
